## INVARIANTS (bắt buộc)
I1. `allowed_actions` do AO CORE sinh (trong `queue.py state`). Coordinator chỉ được chọn MỘT action nằm trong `allowed_actions` của đúng task (hoặc tập `workflow_allowed`). Adapter REJECT action ngoài tập này TRƯỚC khi apply (không gọi Core). Core vẫn là authority cuối: Core từ chối mọi lệnh sai dù Adapter lọt.
I2. Không business/workflow logic trong Adapter (không tự quyết thứ tự, phụ thuộc, tiêu chí xong, retry policy, duyệt). Adapter chỉ dịch: đọc state → hỏi coordinator → kiểm cú pháp + thuộc allowed_actions → gọi lệnh Core → trả kết quả.
I3. Coordinator KHÔNG tạo/sửa brief, worker, acceptance signals của task đã lập. Những trường này nằm trong spec của task (queue) do người lập kế hoạch ghi lúc `add`, bất biến sau đó (có `spec_hash`). Action của coordinator chỉ có các khoá: `action`, `task_id`, `reason`, `next_action`, `blocked_reason`, `context_refs`. Mọi khoá lạ/cấm (`brief`,`worker`,`signal(s)`,`command`,`cmd`,`script`...) → reject `FORBIDDEN_FIELD`.
I4. Không có shell do coordinator viết: Adapter KHÔNG thực thi chuỗi lệnh nào từ coordinator; worker chạy từ `adapters/workers.json` (mẫu lệnh cố định + placeholder do Core điền).
I5. Prompt gửi coordinator chỉ gồm: state JSON (từ `queue.py state --json`), chính sách (mục "Sổ việc bền (durable workflow)" trích từ `${AO_ROOT}\CLAUDE.md` lúc chạy + danh sách `context_refs` của checkpoint mới nhất, nội dung giới hạn), và lược đồ action. KHÔNG có gì từ transcript/phiên Claude.

## C1 — spec của task + lệnh dispatch (trong `queue.py`)
- `queue.py add --id X --title T [--depends-on Y]* [--workflow W] [--worker NAME --brief PATH --signal S ...]`: lưu thêm vào task `workflow`, `worker`, `brief` (đường dẫn tuyệt đối, phải tồn tại), `signals` (list), `spec_hash` = sha256 của JSON chuẩn tắc {worker, brief, signals}. Task KHÔNG có spec vẫn hợp lệ (tương thích T1/T2 cũ) nhưng không dispatch được qua Core (`NO_SPEC`).
- KHÔNG có lệnh CLI nào sửa spec sau `add` (không `edit`/`update`).
- `queue.py dispatch --id X [--retry --reason R] [--by BY]`: Core kiểm task có spec + `spec_hash` khớp (`SPEC_CHANGED` nếu queue.json bị sửa tay), `dispatch` nằm trong allowed_actions của task hiện tại, rồi gọi đúng logic `journal.append` hiện có với worker/brief/signals LẤY TỪ SPEC (không nhận tham số override), áp mọi luật Bước 3 (`ALREADY_ACCEPTED`, `ATTEMPT_IN_FLIGHT`, `RETRY_REQUIRED`, `REASON_REQUIRED`, khoá ghi). In bản ghi dispatched (JSON) như `append`. `--by` lưu vào bản ghi dispatched (`dispatched_by`).
- `queue.py add` trùng id → lỗi như cũ.

## C2 — allowed_actions + needs_owner (trong `queue.py state`)
- `queue.py state --json [--workflow W]`: thêm cho MỖI task `allowed_actions` (list) do Core tính từ trạng thái journal+queue: `waiting`→[]; `ready` có spec→["dispatch"]; `ready` không spec→[] + `blocked:"NO_SPEC"`; `dispatched` (đang bay)→[] (kể cả stale: chỉ gắn cờ); `done` (chưa accepted)→["verify","accept"]; `failed`→["retry"] (retry = dispatch với --retry, cần lý do); `accepted`→[]. Thêm cấp workflow: `workflow_allowed` = ["checkpoint","needs_owner"] + ["done"] CHỈ khi mọi task của workflow đã `accepted`; và `needs_owner`: danh sách workflow có checkpoint mới nhất mang `blocked_reason` bắt đầu `NEEDS_OWNER:` (kèm lý do, by, ts). Mỗi task thêm `workflow`, `worker`, `brief`, `signals`, `spec_hash` (nếu có) để coordinator thấy tiêu chí nhưng KHÔNG sửa.
- Core là nơi DUY NHẤT sinh allowed_actions. Core vẫn từ chối lệnh sai bất kể allowed_actions (kiểm đã có sẵn từ Bước 1–3).

## ADAPTER (thư mục `tools/ao-journal/adapters/`)
Tệp: `ao_adapter.py` (một tệp, mục tiêu ≤ ~350 dòng), `workers.json` (đăng ký worker: tên → mẫu lệnh có placeholder `{brief}` `{task_id}` `{attempt_id}`, `timeout_s`), `capabilities/<coordinator_id>.json`, `README.md` ngắn, `turn_log.jsonl` (nhật ký kiểm toán của Adapter, KHÔNG phải nguồn sự thật; ghi coordinator, hash output thô, action, kết quả; KHÔNG ghi khoá).
Lệnh: `python ao_adapter.py turn --coordinator <id> --workflow <W> [--journal PATH --queue PATH] [--fake-script FILE]` = đúng MỘT lượt (không vòng lặp):
1. `read_state`: gọi `queue.py state --json --workflow W` + nội dung (giới hạn ký tự) các `context_refs` của checkpoint mới nhất + trích mục chính sách từ CLAUDE.md.
2. Nạp `capabilities/<id>.json`; thiếu file/thiếu cờ → từ chối chạy (`CAPABILITY_MISSING`, không đoán). Cờ chỉ `true|false|"unknown"`: `supports_tools, supports_files, supports_vision, supports_long_session, supports_structured_output, supports_resume, supports_subagents`; kèm `invocation`, `max_context_chars`, `env_file` (nếu cần khoá), `notes`. Nếu `supports_structured_output` ≠ true → chế độ "JSON trong văn bản" + phân tích chặt + đánh dấu `degraded:true` trong kết quả.
3. `ask`: gửi prompt (I5) cho backend: `fake` (đọc action từ file `--fake-script`, theo thứ tự từng lượt) hoặc `qwen-cli` (DeepSeek qua Qwen CLI/NVIDIA: `qwen --openai-api-key <đọc từ env_file, KHÔNG in> --openai-base-url https://integrate.api.nvidia.com/v1 -m deepseek-ai/deepseek-v4.1-flash --yolo -p <prompt>`; yêu cầu "chỉ in một JSON"; trích JSON; hỏng → thử lại đúng 1 lần; vẫn hỏng → `MALFORMED_OUTPUT`, KHÔNG đổi state). Backend qwen-cli chạy với thư mục làm việc tạm rỗng và chỉ-đọc ý định (prompt cấm sửa file); Adapter chỉ lấy JSON trong stdout.
4. Kiểm trước khi apply (I1, I3): JSON hợp lệ, đúng khoá; `action` ∈ allowed_actions của `task_id` (hoặc ∈ `workflow_allowed`); lý do bắt buộc với `retry`, `needs_owner`; `checkpoint` cần `next_action`. Sai → `ADAPTER_REJECTED:<mã>` và KHÔNG gọi Core.
5. `apply` (chỉ ánh xạ): `dispatch`/`retry` → `queue.py dispatch --id X [--retry --reason R] --by <coordinator_id>` rồi Adapter chạy worker từ `workers.json` (không shell tùy ý; `subprocess` danh sách đối số; timeout), đọc MÃ THOÁT TIẾN TRÌNH (không dựa dispatch-guard), rồi ghi cơ học `journal.py complete --task-id --attempt-id --status done|failed --summary "worker exit=N ..."` (exit≠0, không khởi động được, hết giờ, worker chưa đăng ký → `failed` kèm lý do mã); `verify` → `journal.py verify-task`; `accept` → `journal.py accept --task-id --by <coordinator_id>`; `checkpoint` → `journal.py checkpoint --workflow W --by <id> --next-action ... --context-ref ...`; `needs_owner` → checkpoint với `--blocked-reason "NEEDS_OWNER: <lý do>"`; `done` → checkpoint `next_action:"WORKFLOW_DONE"` (chỉ khi `done` ∈ workflow_allowed).
6. In JSON kết quả lượt: coordinator, action, task_id, outcome (`APPLIED`/`CORE_REFUSED:<mã>`/`ADAPTER_REJECTED:<mã>`/`MALFORMED_OUTPUT`/`CAPABILITY_MISSING`), state trước/sau (tóm tắt), `degraded`.
Backend/capability có sẵn: `capabilities/fake.json`, `capabilities/deepseek-qwen.json` (chỉ điền cờ tài liệu AO xác nhận; còn lại "unknown"), `capabilities/claude-code.json` (chỉ để khai báo, KHÔNG viết backend Claude). Không viết backend cho Hermes.
